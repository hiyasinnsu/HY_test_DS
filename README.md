# HY_test_DS — スマホで遊べる弾幕シューティング

スマートフォンのブラウザでそのまま遊べる縦スクロール弾幕シューティングです。画面をドラッグして自機を動かすだけでショットは自動。ボムと低速は画面下のボタンで操作します。難易度は Easy / Normal / Hard の 3 種類、ステージ 1 は雑魚ウェーブからボス「星霊アストラル・セラフ」の 5 段階のスペルカードへと続きます。画像も音声もすべてプログラム生成で、外部アセットはありません。

- 遊ぶ: <https://hiyasinnsu.github.io/HY_test_DS/>
- ソース: <https://github.com/hiyasinnsu/HY_test_DS>

## 遊び方

### スマートフォン

| 操作 | 方法 |
| --- | --- |
| 移動 | 画面をドラッグ（指の移動量に合わせて自機が動く相対移動。指で自機が隠れません） |
| ショット | 自動。押し続ける必要はありません |
| ボム | 画面下部の「ボム」ボタン |
| 低速移動 | 画面下部の「低速」ボタンを押している間 |
| ポーズ | 画面右上の「ポーズ」ボタン |

- タイトル画面で難易度を選び、スタートで開始します。
- ボムは一定時間、弾を消しながら敵にダメージを与えます。
- 被弾すると残機が減り、残機が 0 になるとゲームオーバー。ポーズ画面からリトライできます。
- プレイ中のページスクロールとピンチズームは無効化してあります。

### PC

マウスのドラッグでもタッチと同じように遊べます。キーボードでも操作できます。

| 操作 | キー |
| --- | --- |
| 移動 | 矢印キー / W A S D |
| 低速移動 | Shift（押している間） |
| ボム | Z / J |
| ポーズ | Esc / P |
| スタート・リトライ | Enter / Space |

## 難易度

弾速・弾数・敵 HP・初期残機・ボム数・スコア倍率が難易度ごとに変化します。

| 難易度 | 弾速 | 弾数 | 敵 HP | ボス HP | 初期残機 | 初期ボム | スコア倍率 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Easy | ×0.82 | ×0.70 | ×0.80 | ×0.72 | 4 | 4 | ×0.70 |
| Normal | ×1.00 | ×1.00 | ×1.00 | ×1.00 | 3 | 3 | ×1.00 |
| Hard | ×1.13 | ×1.30 | ×1.25 | ×1.20 | 2 | 2 | ×1.50 |

## 収録内容

- ステージ 1: 雑魚敵のウェーブ → ボス「星霊アストラル・セラフ」戦（スペルカード 5 段階）
- スコア / グレイズ（かすり）/ 残機 / ボム
- ハイスコアは localStorage に保存され、リロードしても残ります
- タイトル → 難易度選択 → プレイ → ポーズ / ゲームオーバー / クリア の画面遷移

## 技術構成

- Vite 8 + TypeScript。描画は Canvas2D。ランタイム依存パッケージはゼロ（devDependencies のみ）
- 画像・音声はすべてプログラム生成。弾スプライトはオフスクリーンに事前描画し、プールした弾を `drawImage` で描画
- シミュレーションは固定タイムステップ（1/60 秒）で更新し、描画から分離
- テストは Vitest（`npm test`）
- `base: './'` の相対パスでビルドするため、GitHub Pages のプロジェクトページ配下でもそのまま動作

## 開発

Node.js 24 系（GitHub Actions と同じ）を想定しています。

```sh
npm install       # 依存関係のインストール
npm run dev       # 開発サーバー（http://localhost:5173/）
npm test          # 単体テスト（Vitest）
npm run build     # 型チェック + 本番ビルド → dist/
npm run preview   # ビルド結果をローカル配信（http://localhost:4173/）
npm run smoke     # ビルド後、ヘッドレスDOM上で実プレイを数千フレーム駆動して実行時エラーを検出
```

- スマートフォン実機で確認する場合は、PC と同じ LAN につないで `npm run dev` が表示する Network URL を開きます。
- `npm run preview` のポートは環境変数 `PORT` で変更できます。

## 公開

GitHub Pages で公開しています。`main` ブランチに push すると `.github/workflows/deploy.yml` が「依存関係のインストール → テスト → ビルド → デプロイ」を実行します（`npm ci`、`npm test`、`npm run build`、`dist/` を artifact として公開）。

- 初回のみ、リポジトリの Settings → Pages → Source が「GitHub Actions」になっているか確認してください。ワークフローは `actions/configure-pages` の `enablement: true` で API からの有効化も試みますが、権限などの理由で失敗する場合はこの手動設定が必要です。
- 手動デプロイは Actions タブ →「Deploy to GitHub Pages」→ Run workflow から実行できます。

## 既知の制限

- iOS Safari は全画面 API に対応していないため、全画面表示はできません。
- 端末の性能によってはフレームレートが低下する場合があります。
- 効果音はブラウザの自動再生制限により、最初のタップ以降に有効になります。
- ハイスコアなどの保存先はブラウザの localStorage です。別端末やシークレットウィンドウには引き継がれません。
